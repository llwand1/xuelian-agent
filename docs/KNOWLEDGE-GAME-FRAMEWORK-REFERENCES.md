# 知识游戏框架：参考项目与首轮实现决策

2026-10-16。结论：**资料足以开始一个范围受控的框架纵向验证，但还不足以批准全量重写或锁死画面引擎。** 本轮查阅官方文档、许可和选定源码，没有安装/运行这些引擎，也没有把第三方实现并入产品。

## 1. 调研范围

目标是“可编写、分享、Fork、更新的像素知识情景框架”，不是再寻找泰拉瑞亚复刻。按三种接近程度看待参考：

- 视觉与人物活动接近：AI Town、Generative Agents。
- 实体/行为/场景创作机制接近：KAPLAY、Excalibur、ct.js、GDevelop。
- 分享二创、资产格式、学习事件接近：MakeCode Arcade、LDtk、H5P。

没有把任何一个项目认定为我们的完整替代品；本轮没有找到同时满足全部目标的直接底座，这也不是“世界上没有同类”的结论。

## 2. 最值得参考的项目

### KAPLAY：可组合实体与编码体验

[仓库](https://github.com/kaplayjs/kaplay) · [组件文档](https://kaplayjs.com/docs/guides/components/) · 代码 MIT。

对象由外观、位置、碰撞等组件组合，并允许自定义组件。适合借鉴“人物/建筑是模板，而非不可突破的继承分类”。已读状态组件与自定义组件示例；状态组件有转换约束、进入/退出钩子。

**使用建议：首个浏览器表现层技术验证候选，不直接当通用知识内核。** 核心状态/命令不要以第三方 GameObj 为持久格式，回调函数也不等于可存档的内容协议。源码检视的 main 是 4000 alpha，而当日 npm latest 是 3001.0.19；二者不能混着当成同一稳定 API，集成验证应锁定稳定版本并重查所用接口。

### Excalibur：持续动作与生命周期

[仓库](https://github.com/excaliburjs/Excalibur) · [动作教程](https://excaliburjs.com/docs/actions-primer/) · 代码 BSD-2-Clause。

Action 接口有 update/isComplete/reset/stop，动作队列发出开始和完成事件。对“走到机器旁→等待→操作→再移动”这类像素人物情景尤其有参考价值。

**使用建议：动作模型的重点参考，也是表现引擎备选；不是与 KAPLAY 同时引入。** 我们还需要动作失败、取消、共享资源占用、版本化输入和学习证据等语义，不能把引擎事件直接当学习事实。检视源码及当日 npm latest 均为 0.32.0。

### ct.js：模板、行为组合与模块导出

[仓库](https://github.com/ct-js/ct-js) · [行为文档](https://docs.ctjs.rocks/behaviors.html) · 代码 MIT。

已读行为运行时和导出代码：模板/房间可组合行为，动态行为有添加/移除钩子；部分静态行为在导出阶段编入。适合借鉴“一套行为可应用到多种实体”，以及创作数据到可玩构建的流程。

**使用建议：重点参考创作 SDK、行为复用、导出管线。** 不整体 Fork 桌面编辑器；其打包执行的 JS 也不能直接视作陌生作品的安全沙箱。

### GDevelop：自定义行为如何成为正式扩展

[仓库](https://github.com/4ian/GDevelop) · [事件式自定义行为](https://wiki.gdevelop.io/gdevelop5/behaviors/events-based-behaviors/) · GDJS 等主要代码目录 MIT，商标另列。

已读 RuntimeBehavior 的 owner、激活状态、更新/热加载生命周期；官方创作方式允许把事件编成可复用行为。适合参考行为参数、命名空间、帮助信息和扩展的编辑体验。

**使用建议：参考扩展模型，不在第一阶段复制整套 IDE/云平台。** GitHub API 对仓库许可给出 NOASSERTION，但根许可指向各目录，已另查 GDJS/LICENSE.md 的 MIT 正文；自动标签不能替代具体文件检查。

### MakeCode Arcade：分享即允许复制编辑

[仓库](https://github.com/microsoft/pxt-arcade) · [分享机制](https://arcade.makecode.com/share) · 仓库代码 MIT。

分享者交付可运行内容，接收者可查看代码、复制编辑，再发布自己的链接；扩展还有仅加载资源的 asset-pack 模式。**这是产品闭环的重点参考。**

本次确认其 game 库通过 pxt-common-packages 引用，不误把 pxt-arcade 一个仓库当成完整运行时。学习“源码与可玩版本并存、修改不覆盖原作”，不复制其多仓编译体系作为首轮依赖。

### LDtk：地图与场景实体的开放数据

[仓库](https://github.com/deepnight/ldtk) · [JSON 格式与 Schema](https://ldtk.io/json/) · 编辑器代码 MIT。

已读最小 JSON Schema：关卡、图层、实体实例、稳定标识等有明确定义。**建议先接入有限子集的导入适配，而不是先自研完整地图编辑器。** 明确格式版本、资源路径及不支持字段；它是关卡工具，不替代行为、学习或脚本运行时。项目自带的美术素材仍需分别核对。

### AI Town / Generative Agents：人物控制与认知流程

[AI Town](https://github.com/a16z-infra/ai-town) 的代码 MIT，已读 Game、Agent 和输入封装：Agent 关联玩家实体，通过待处理操作和输入影响世界，并有超时/状态管理。它最接近“像素人物在情景中活动”的外观，但实现围绕 Convex，不宜让我们的离线内核依赖它。该项目同时有本地运行方案，不能称其只能使用云服务。

[Generative Agents](https://github.com/joonspk-research/generative_agents) 代码 Apache-2.0，已读 perceive/plan/execute。适合参考观察→计划→执行，以及对空间/物体的语义定位；不直接沿用字符串计划作为我们的执行命令。该研究仓库检视的提交停留在 2023 年，不当作现代生产框架；画面资源的作者/许可另核，不因代码许可直接整体打包。

**两者均作为可选 AI 控制器参考，而不是框架必需运行条件。** 人类、规则控制器、外部模型应最终提交同一种受校验动作。普通游玩不需要为每一帧调用模型。

### H5P：学习作品打包、宿主接口与学习事件

[PHP 核心仓库](https://github.com/h5p/h5p-php-library) · [.h5p 规范](https://h5p.org/node/2463) · [xAPI 事件](https://h5p.org/node/2397)。本项主要核对官方规范与仓库许可，没有获得本地固定提交的完整源码快照。

内容、代码库、依赖与语义定义分开打包，学习活动通过事件交给宿主。适合参考作品包/行为库/学习记录的边界，以及未来学习系统互通。

**不是像素游戏引擎，也不计划首轮引入 PHP/LMS。** 当前 h5p-php-library 是 GPLv3，不能把“H5P”笼统写成全部 MIT。此处参考格式和接口思想，具体代码复用另作许可决策，不默认承诺原生 H5P 文件兼容。

## 3. 推荐的组合，而不是拼装九套框架

```text
我们自己维护：
  可序列化的实体/组件状态、动作与事实事件、规则、学习证据、作品与版本契约

首个技术验证：
  KAPLAY 稳定版作为浏览器表现层候选；不把其对象传进公共协议

重点借鉴：
  Excalibur 动作生命周期；ct.js / GDevelop 行为与扩展模型
  LDtk 场景数据导入；MakeCode 分享二创；H5P 内容/依赖/学习事件分层

可选适配：
  StudentBuddy 对话与学习服务；AI Town / Generative Agents 的控制器思路
```

这是工程建议而非性能结论。暂不切换 Godot、不重写当前矿境、不自动安装任何上述依赖。若首个候选无法满足同场景验证，再比较 Excalibur 或其他表现方案，而不是同时维护多套引擎。

## 4. 开始实现前真正还缺的证据

| 技术闸门 | 首轮必须实测 |
|---|---|
| 无头与可恢复性 | Node 无 DOM 运行规则；相同初态/种子/命令得到相同结果；中途保存恢复后持续动作仍正确，不靠保存函数闭包 |
| 自由交互 | 人类/规则/模拟 Agent 换控制器不换实体；多人参与、无目标动作、持续动作取消和条件不满足不产生假成功事件 |
| 表现层 | 原生中文清晰；角色能在像素场景移动/交互；与已有矿境手感做对照；记录启动体积和性能，不凭介绍页决定 |
| 二创与更新 | 新项目仅注册模块即可增加机制；打包后别人可运行并修改；父版本/依赖可追溯；作品更新不混入或清除个人学习数据 |
| 扩展执行边界 | 官方/本地可信模块先跑通；陌生代码自动分发前完成隔离、CPU/内存/消息预算与终止测试。组件系统或 Worker 名称不等于已验证的沙箱 |

这些是需要写原型获得的证据，不是继续搜几十个仓库就能回答的问题。首轮无需做成熟社区、可视化全编辑器、复杂战斗经济或完整公网大厅。

## 5. 首个可运行切片

建议用“电路工坊”做新框架参考情景，不改变原矿境：人物、助手、工坊、导线、开关、灯；组件组合定义能力；支持递交物品、连接、操作、等待和取消。一个教学规则模块决定连接/开关条件下的状态与结果，不把它冒充专业电路仿真。

同一场景应能自动演示，也能由玩家接管；动画由事实驱动，不能到时间就假装任务完成。玩家的预测/操作/解释产生带作品版本的学习证据。首轮 Agent 适配使用明示的规则测试控制器，无外部模型时不伪称 AI 推理。

随后用第二种不同机制的作品检验接口；原矿境再作为迁移样本。两种作品均不修改内核，才进入接口冻结和更大范围重构。
