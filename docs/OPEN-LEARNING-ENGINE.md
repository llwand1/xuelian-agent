# 不定式学习引擎 · 架构决策与实施边界

2026-10-16 · ADR / 协议 v1。核心主张：**AI 时代，每个人都可以是开发者；稳定学习事实，让体验、世界与 Agent 持续可塑。** 这是项目重点创新方向之一，不声称首创或排他技术。

## 1. 同级领域，不把游戏塞进页面组件

```text
宿主应用：身份、许可、存储、可观测性、版本迁移
 ├─ 学习域：资料、词条、题目快照、作答证据、复习
 ├─ 游戏域：世界、角色、物理、挖掘、NPC、魔法
 └─ 开放引擎 @sb/open-engine
      ├─ AgentKernel：定义 → 提案 → 差异 → 用户应用 → 回滚新版本
      └─ AuthorityRoom：会话 → 顺序指令 → 固定 tick → 权威快照
              ↑ 类型化适配器 / 能力 broker ↓
      内容包 / 世界蓝图 / 主体模型网关 / MCP / 外部本地 Agent
```

学习域不依赖 Canvas、帧率或联网成功；游戏域不能自行决定答案正确性。题目和答案快照复用主体 `buildQuestion / gradeAnswer / applyQuizAttempt`；后续正式接入仍需主体存储和复习适配器，不创建平行的正式题库。游戏帧不能等待 AI。AI 负责提出可校验数据，内核负责确定性执行。

## 2. 开放协议，共用治理，不混用传输

| 协议 | 身份 / 版本 | 内容 | 作用域 |
|---|---|---|---|
| `studentbuddy.game-extension` | apiVersion、包 id | 像素形象、NPC、能力与类型化效果 | 生成内容，不执行脚本 |
| `studentbuddy.world` | apiVersion、id、revision | 地图、出生点、学习分区、依赖包 | 编译预览后加载 |
| `studentbuddy.agent` | apiVersion、id、revision | 提示词、策略、工作流、能力集合 | 配置演进，不自行授予权限 |
| `studentbuddy.room.command` / `.snapshot` | apiVersion、sequence / revision | 玩家意图、权威世界、私有学习快照 | 网络传输无关 |
| `studentbuddy.companion-turn` | apiVersion、sessionId、worldId、sequence | Agent 同伴的移动/跳跃意图与纯文本回复 | 共享玩家物理，换世界或恢复时撤销控制 |

统一规则：命名空间 id、显式版本、拒绝未知字段、有界输入、引用校验、失败不改旧状态、宿主保存。Schema 保证结构；出生点/入口可挖、版本冲突、能力授权仍需语义校验。v1 不接受第三方脚本 URL，不动态 `eval`。

现有插件 manifest v2 继续负责连接、身份、工具发现、逐次确认、撤销与审计。**内容包不是第二个 MCP 标准，浏览器进程内 API 也不是裸 HTTP 服务。** 后续插件工具映射到 `world.validate / world.preview / agent.propose` 等宿主能力；模型可提案，不能调用用户应用入口。桌面文件权限继续遵循 [工作区规范](DESKTOP-AGENT-WORKSPACE-SPEC.md)。

## 3. Agent 自改进

已实现的纯内核在 `packages/open-engine/src/agent-kernel.mjs`：

1. 当前 `baseRevision` + 完整下一版定义 + 理由；只接受同 id、revision+1。
2. 校验定义和宿主 grants、计算字段差异；提案本身不生效。
3. 用户确认界面持有独立 approval token。外部公开 API 只暴露读取、提案和已授权能力调用，**不暴露 apply / rollback**。
4. 应用后清除旧待确认提案、追加历史；并发旧提案失败。
5. 回滚复制旧配置为新版本，不抹除中间历史；最多 64 版，满后要求导出，不静默裁剪。待确认提案最多 16 份，不写入恢复存档自动执行。

原型能力：`world.inspect / world.preview / content.inspect / ability.recall`，由 broker 显式映射。提示词和工作流策略当前仅保存与导出，**尚未喂给正式主体 Agent 模型循环**；真实发生的是配置演进与能力分发。改宿主源码属于未来另一条开发工作流，不能冒充本次配置自改进。也不涉及模型权重训练。

approval token 是同进程职责隔离，不是恶意同源 JavaScript 的安全沙箱；正式主程序需服务端 owner 校验、一次确认、持久事务和撤销检查。提案不能扩大 grants，复用桌面 Agent/插件权限也不能突破父任务范围。导出定义与历史不含模型密钥。

## 4. 联机准备：权威在服务端

`AuthorityRoom` 注入模拟适配器，不依赖浏览器、HTTP 或模型提供商。玩家仅提交 `input / recall / torch / answer`，不能提交坐标覆盖、破坏结果、地图或内容包。房间创建时锁定世界/词条/内容；热更新需要独立房主提案与全员版本协商，v1 暂不提供。

- 固定步长 1/60 秒。每玩家独立输入、物理状态、抽题序列、发现题目与作答证据；方块/火把共享，NPC 每 tick 模拟一次。
- 每会话严格连续 sequence；仅缓存最近一条回执，精确重发幂等。旧序号、缺口或同序不同内容失败并要求重取快照，不承诺无限重放。
- 输入租约 15 tick，断网不永久移动/挖掘；jumpPressed 单 tick 消费。最多 8 玩家，每 60 tick 最多 120 条新指令。
- 公共 players/world 与请求者 self.learning 分开；不广播他人的题目、答案或正确率。这里是玩家间隔离，**房间宿主仍处理学习数据，不是端到端加密**。
- room revision、world revision、content fingerprint。地形未变省略 cells；未知/旧 world revision 返回完整有界地图，持原会话可重新拉快照。
- 本地快照轮询验证传输，后续可替换 WebSocket，不改指令内核。当前无客户端预测、插值、延迟补偿、跨服务恢复。

独立 MVP 的 `room-server.mjs` 是可运行 Node 内置 HTTP 适配器：127.0.0.1:18841、随机 Bearer 会话、Host/Origin 检查、16 KiB 指令限制、空闲清理。双客户端真实 HTTP 测试覆盖会话隔离、幂等重发、重取快照和退出。它不是公网服务器：**没有账号、TLS、持久房间、邀请大厅、完备反作弊或房主迁移；浏览器游戏仍是单机，未加入可点击联机大厅。**

## 6. 接入顺序与验收

1. 主体学习适配器：按 owner 写正式学习事件，世界/题目快照可追踪；不能因重发重复计作答或奖励。
2. 主体 Agent 定义存储与模型循环：profile 作为配置输入；服务端确认、修订号校验、审计与事务原子保存，恢复不自动重放能力。
3. 单机/房间共用动作入口；补浏览器房间客户端、同伴渲染、插值/预测，保持已认可的跳跃和挖矿手感。
4. 上线前补账号/邀请、TLS、房间持久化、学习数据托管说明、断线恢复、限流与压力/故障测试；不能把回环服务改成 0.0.0.0 就称上线。

本包验证：`npm run test:open-engine`。原型验证：`node --test tests/*.test.mjs`（含 HTTP 真双客户端、地图和存档回归）。协议变更需同步 Schema、示例、适配器与测试；不兼容版本显式拒绝。

## 7. AI 原生玩家与表现层（MVP 0.5）

NPC 是出生/素材定义，不是不同的一套生物物理。运行时按 player 实体、human/agent 控制器、learner/companion 角色区分。独立原型复用 stepPlayer 执行搭子意图，离线 follow/wait 只是明示的规则控制器；外部 Agent 读取局部观察、对话和可见题面，再提交受限输入与纯文本回复。没有连接模型时不宣称生成式智能。

CompanionSession 位于 @sb/open-engine；与房间共用输入校验，有连续序号、精确最近重发、世界/会话绑定、250ms 单调时钟租约。消息持久化，控制会话不恢复。单机搭子不替学习者写答题证据；房间 Agent 是独立 peer，可有自己的题目和作答。controller 元数据不赋予额外权限。主体模型循环/插件到该接口的实际适配仍待接入。

魔法与工具统一投影为物品，legacy ability.kind 仅为兼容标签。快捷格/背包是表现，动作仍走领域 command；学习域不依赖背包经济。像素美术与可读文本分层：画布只画像素，名字/回复由原生 DOM 按屏幕坐标渲染，不把中文缩到 7px 后放大。
