# 悬浮球引路灯与实时视频（本地桌面 0.2.205）

## 为什么这样改

沿用「同一套理念换表现形式、加强功能与学习主线联动」：把提醒集中到已有悬浮球与引路灯，而不是不断增加怪物提示或独立战斗入口。视频始终是当前学习材料，关闭、大小切换与截图都不应打断正在看的内容。

## 入口与提醒

- 主应用不再挂载新怪物提醒。矿境里的真实怪物和学习遭遇保留。
- 常规导航及引路灯功能表不再展示 PK；历史 `#/pk` 路由兼容。非输入场景按 ↑↑↓↓←→←→BA 可打开彩蛋；输入框、画布、弹窗与组合输入不会误触。
- 悬浮球设置新增「悬浮球引路灯提醒」开关和手动打开按钮。开关按本人存储。
- 复用引路灯当前现场实际生成的建议（包括规则回退），不另请求模型生成同义提醒；保留原会话和页面。点击「打开引路灯」才展开相应现场，不自动替用户发送消息或执行建议。
- 首次至少等待一分钟，之后半小时冷却，可延后十分钟；建议现场三分钟失效，三十秒续期。忙碌、隐藏、番茄休息、高优先级练习/每日任务时不抢提醒。
- 服务端复查会话归属、序号与有效期；多窗口只选择最新现场。原生气泡按 ID 关闭，旧提醒清理不能误关新邀请。恢复工作区期间的打开请求排队，待引路灯挂载后处理。

## 视频交互

- 对话来源与独立视频搜索页共用 `VideoPlayer`。控制栏固定提供关闭 ×、悬浮/还原、放大/退出放大、截取当前画面。
- 悬浮是**应用页面内**可拖动小窗，不是系统级置顶或跨应用画中画。窗口随视口钳制，顶部控制栏始终在第三方 iframe 外。
- 放大是可逆的页内覆盖层，不调用浏览器全屏；禁用第三方 iframe 接管全屏。还原按钮与父页面 Escape 均可退出。
- 切换大小只改变同一 iframe 的样式，不卸载重播。关闭才卸载播放器。来源面板的入场 transform 在视频存在时取消，避免固定小窗被祖先裁剪。
- 桌面截图用 WebView2 `CapturePreviewAsync` 捕获该 WebView 当前实际渲染画面，再依据即时 iframe 边界及像素比例裁剪。请求 ID 校验、单窗口并发限制、超时/取消和大小限制均保留；不读取整块桌面，不拿封面或旧截图冒充当前帧。
- 普通浏览器需用户授权共享画面；支持 Region Capture 时裁剪播放器，否则明确标为「共享画面截图」。结束后立即停止共享轨道。
- 截图先预览，支持保存或附到 AI 输入框；点击附入不等于发送。附入时还原播放器，便于继续提问。

## 边界

第三方视频仍由其公开播放器提供；网络、登录或平台限制不由截图功能绕过。该版本只更新本机安装，未发布网站或公共更新通道，不修改历史学习记录与每日任务目标。

技术依据：[WebView2 当前预览截图](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.capturepreviewasync?view=webview2-dotnet-1.0.4022.49)、[浏览器显示捕获接口](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)。
